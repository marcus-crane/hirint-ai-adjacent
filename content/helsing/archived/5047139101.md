## **The role**

Developing modern combat systems, training tactical AI and conducting large-scale operational analysis (OA) all depend on a simulation backbone that bridges two traditionally separate worlds. One is cloud-scale, faster-than-real-time constructive simulation, such as AFSIM. The other is hard real-time, distributed simulation for software- and hardware-in-the-loop (SIL/HIL) testing and live, virtual and constructive (LVC) environments.

As a Simulation Backend Engineer on our Simulation team, you will build and evolve the core runtime, execution engine and distributed interoperability layer of our synthetic environment. You will solve complex systems-engineering problems in logical and real-time clock synchronisation, deterministic execution, multi-rate scheduling and low-latency state distribution. Working in Rust and C++, you will design the backbone infrastructure and interoperability gateways (HLA, DIS, RPR-FOM) that allow heterogeneous models, AI agents and physical test rigs to run coherently, whether on a single node or across distributed deployments. Your work will let the same models support everything from overnight Monte Carlo campaigns to live rig testing, without having to be rebuilt for each use.

## The day-to-day

* Design, build and optimise our core simulation runtime in Rust and C++, supporting faster-than-real-time execution (constructive, Monte Carlo and AI training) and wall-clock real-time execution (SIL/HIL and interactive LVC), from low-overhead, in-process single-node runs to multi-node, multi-site federations
* Design and implement federated time-management mechanisms, covering logical time progression, lookahead, time-advance requests and grants, multi-rate execution, and transitions between paced and unpaced simulation modes
* Build and maintain distributed simulation gateways and protocol adapters (e.g. DIS, HLA, RPR-FOM, TENA, SIMPLE), mapping external standards cleanly onto our internal canonical data model
* Solve distributed state synchronisation problems, including dead reckoning, latency compensation, ownership arbitration and deterministic event ordering across networked nodes
* Integrate legacy and partner simulation models (mainly C++, Python and MATLAB/Simulink) and AFSIM-class constructive frameworks into the backbone through clean foreign function interface (FFI) and adapter boundaries
* Deliver the infrastructure capabilities that production simulation depends on: deterministic recording and replay, seed-based reproducibility, fault injection and execution telemetry
* Collaborate with kill-chain domain architects, AI engineers and rig and HIL engineers to ensure the backend meets strict latency, throughput and determinism requirements

## **You should apply if you**

* Write production-grade backend and systems code in C++ or Rust, are keen to use Rust as your primary language, and have worked with Python or C/C++ FFI boundaries for model integration
* Have built or worked closely with faster-than-real-time constructive simulation engines (e.g. AFSIM or comparable engagement- and mission-level frameworks) or real-time simulation systems (e.g. SIL/HIL rigs, training simulators, LVC), and understand what each demands of a shared backbone
* Understand simulation time management in detail, including logical versus wall-clock time, discrete-event versus time-stepped scheduling, multi-rate execution loops, jitter and determinism
* Have applied distributed simulation standards in practice, such as DIS, HLA (IEEE 1516) and RPR-FOM, or comparable standards such as TENA and SIMPLE, and understand the runtime trade-offs between different RTIs and transport layers
* Understand the infrastructure, networking and compute requirements of simulation workloads, from containerised, high-throughput cloud execution to low-latency, on-premise real-time clusters
* Apply engineering rigour to deterministic execution, memory safety, low-overhead serialisation and clean API design
