Saronic Technologies is a leader in revolutionizing autonomy at sea, dedicated to developing state-of-the-art solutions that enhance maritime operations through autonomous and intelligent platforms.

## Job Overview

Saronic is seeking a Systems Software Test Engineer to own and advance the testing strategy for the software stack running on every Saronic vessel. You will help unify and expand our existing verification capabilities, including Hardware-in-the-Loop (HITL) stations, virtual machine (VM) integration tests, replay-based evaluation, and simulation, into a cohesive, extensible testing platform.

You will also introduce and scale advanced testing methodologies, including property-based testing, protocol and message-bus fuzzing, deterministic simulation, and fault injection for safety-critical state machines.

This is a software engineering role focused on building the infrastructure and tools that give engineers confidence in shipping reliable software to autonomous vessels operating in the open ocean. You will work closely with our autonomy, perception, systems, controls, networking, and infrastructure teams to develop end-to-end validation frameworks that run as native Rust unit and property tests, VM-based integration tests, on physical HITL stations connected to real hardware, and in simulation using captured fleet data.

Your work will directly impact mission reliability by identifying edge cases early, strengthening system-level validation, and ensuring that vessel software is rigorously tested before deployment.

## Responsibilities

### Test Strategy and Verification Architecture

* Own and drive testing initiatives for Saronic's system software, including the HITL test catalog, station orchestrator, HITL-to-VM bridge framework, and NixOS-based VM integration test suite.
* Design and implement a unified verification strategy that combines Rust unit and property tests, VM-based integration tests, HITL testing, and replay- and simulation-based scenario testing.
* Establish a risk-based testing framework that determines the appropriate test type for each risk class, balancing coverage, execution cost, and confidence.
* Develop reusable testing patterns and infrastructure that enable engineers across the organization to author, extend, and maintain high-quality tests.

### Property-Based Testing, Simulation, and Fuzzing

* Expand property-based and deterministic simulation testing across the software stack.
* Develop invariant-based tests for critical components, including planners, trackers, schedulers, state machines, codecs, inter-process communication (IPC) framing, and certificate and identity systems.
* Establish shared invariant-testing patterns that other engineers can readily adopt.
* Build fuzz-testing infrastructure from the ground up, identifying high-value attack surfaces, developing test harnesses, integrating continuous execution, and triaging or resolving findings.
* Develop fault-injection and chaos-testing capabilities, including process termination, network partitions, time skew, CAN bus interference, and sensor dropouts.
* Ensure fault-injection capabilities can be reused across property-based, simulation, and HITL testing workflows.

### HITL Infrastructure and Integration Testing

* Expand the HITL test catalog and improve coverage in underserved areas of the software stack.
* Extend VM-based integration tests to exercise real hardware interfaces and end-to-end system behavior.
* Treat HITL stations as a first-class software product by improving their reliability, observability, reproducibility, and maintainability.
* Harden CI scheduling and orchestration systems responsible for reservations and test execution across multiple physical HITL stations.
* Reduce flaky tests and improve test-result dashboards, analytics, and debugging workflows.
* Integrate onboard test infrastructure with cloud-based artifact storage, MCAP capture and replay, metrics collection and storage, fleet-data retrieval, and existing CI systems.
* Enable engineers to author tests once and run them locally, in CI, on HITL stations, or against historical fleet data with minimal friction.

### Systems Engineering and Cross-Functional Collaboration

* Partner with engineers across autonomy, perception, systems, controls, networking, infrastructure, and hardware to identify system-level risks and develop effective validation strategies.
* Participate in design reviews and collaborate with feature owners on test plans before implementation.
* Write and maintain high-value tests that expose real system defects, diagnose failures, and prevent regressions.
* Develop and maintain software systems using NixOS to support autonomous navigation, control, and communication across surface vessels.
* Collaborate with hardware engineers to integrate software with vessel systems and validate end-to-end operation.
* Support testing and validation of controls, sensor fusion, network communications, and other mission-critical software components as needed.
* Optimize and validate communications in low-bandwidth, high-latency environments.
* Troubleshoot complex software issues, perform root-cause analysis, and improve system reliability and performance.
* Travel to test sites as needed to validate software and testing infrastructure on operational vessels.

### Engineering Excellence and Documentation

* Maintain high standards for code quality, scalability, reliability, and maintainability through code reviews and sound software engineering practices.
* Document verification architecture, testing patterns, operational runbooks, and test results so other engineers can independently extend and operate the platform.
* Continuously evaluate emerging tools, techniques, and industry best practices relevant to autonomous systems verification and reliability.
