**About the Role**  
This role builds testing into Dive-XL designs and gives Production the test capability to find faults early. The aim is that faults are found at the lowest level of assembly where they can be found, problems reach design teams with the data needed to fix them, and recurring problems are fixed at their source in the design. The role sits within the Platform Engineering organisation and works closely with Manufacturing Engineering and Manufacturing Operations.  
The role starts with the Dive-XL vehicle, built in Australia. Once the approach is proven there, it extends in agreed stages to other Maritime Engineering products and our US sites. At each stage, the responsibilities below apply to the products and sites then in scope, and the role hands the capability it builds to the teams that will run it before moving on.  
This is a senior technical leadership role at Staff level, and its output is engineering: test strategies, test modes and interfaces, test tooling and design changes. It needs deep technical judgement across electronics, firmware and software, and the credibility to influence design engineers and production teams. The role builds software and tooling for test stations and factory acceptance testing (FAT). Running them day to day, station hardware, fixtures and calibration, first-line triage and field support are outside its scope.  
  
**Key Responsibilities**  
**Test-Ready Design**

* From the start of each new Dive-XL design, set its test strategy with the design engineers: what is checked at board, subsystem and vehicle level (electrical performance as well as functional behaviour), with what limits, test points and firmware test modes, and how each test is run
* Own the firmware and software parts of each test strategy, and work with the electrical and mechanical design engineers on their parts. Specify and verify firmware test modes, and provide a reference implementation of each new kind for the owning firmware teams to adopt
* Within delegated authority, set testability requirements, sign off testability at design reviews, and own the standards that make products testable: the firmware test-mode specification, device interface definitions and the factory record (each unit's identity and as-built configuration). Work with Configuration Management to add a test-impact check to engineering changes
* Extend testability across existing Dive-XL boards and subsystems, in a priority order agreed with Platform leadership and informed by production data: built-in self-test, test modes, factory records and a defined starting software baseline for newly built boards

**Test Platform and Tooling**

* Build the shared software that engineering test and production test both use to talk to devices: machine-readable device definitions versioned with the firmware, versioned command interfaces, and a client library for hardware-in-the-loop (HITL) rigs and production stations. Keep it open and not tied to any one test framework
* With the firmware and application software teams, add an automated check to their release process that production test still works with each new firmware and application version
* With Manufacturing Engineering, deliver automated test for a first Dive-XL subsystem that runs independently of the application software release cycle, and hand it over, with acceptance tests, to Manufacturing Engineering's test engineers
* Treat production test tooling as a product, with users, requirements, releases, documentation and a roadmap, and hand it over to its long-term owner when it is ready. With Manufacturing Engineering, make the software on test stations repeatable to deploy from a version-pinned release (for example NixOS), so a new station or site is set up from a release, not by hand

**Closing the Loop with Production**

* Take the software and test side of each first-of-type build of a new design through to readiness, so problems are found and fixed before volume production
* With Manufacturing Engineering and Manufacturing Operations, build fault-reporting and diagnostic tools so problems arrive with the data needed to solve them, and Production can resolve more problems itself
* Use escalations from Production to find systemic causes: lead the root-cause analysis of repeat and systemic problems across hardware, firmware, software and test, and drive a lasting fix at the source (the design, the test or the tooling) with the owning teams
* Build FAT tooling for Manufacturing Engineering and Manufacturing Operations to adopt: scripted acceptance runs with machine-readable results, automated unit setup and vehicle-level diagnostics. Use FAT data to propose procedure changes, with evidence, for the procedure owner to consider
* Decide software, configuration and test questions within delegated authority (for example, a firmware version mismatch on a built unit, or whether a failure is a defect or a design limit), and escalate decisions beyond that authority

**Technical Leadership, Collaboration and Metrics**

* Work as one team with Platform's mechanical and electrical engineers on production readiness: shared readiness criteria for first-of-type builds, common quality-ticket categories, one metrics view and a joint review of FAT teardowns, with this role responsible for the software and test parts
* Provide technical leadership to the engineers and contractors working on test capability, and work with Manufacturing Engineering's test engineers so Production can own and extend it
* With Platform's mechanical and electrical engineers and Manufacturing Engineering, track and report shared results: how often Production needs to call in design engineers during first-of-type builds, quality tickets on first-of-type builds, faults caught at a lower level of assembly, FAT first-pass yield, time to root cause, teardown events, and escalations from Production per vehicle built
* Build strong working relationships across Platform's engineering, software and firmware teams, Manufacturing Engineering, Manufacturing Operations, New Product Introduction, Quality and Program Management
* Take part in production readiness reviews, design reviews (DFM/DFA/DFT) and engineering change reviews as the software and test voice
* As the role extends, write playbooks that take the approach to new product lines and sites

**Key Competencies & Attributes**

* **Engineering Judgement:** Technical depth across electronics, firmware and software, with production pragmatism; sound decisions under time pressure without over-engineering
* **Systems and Test Thinking:** Sees the product, its tests and the factory as one system; decides what to check at each level of assembly and catches faults as early as possible
* **Design Authority Integrity:** Protects safety and quality under schedule pressure; knows the limits of delegated authority and escalates when needed
* **Influence & Communication:** Credible with design engineers, technicians and leaders; changes how design and production teams work together; clear in writing
* **Product and Handover Mindset:** Builds tooling as a product, and hands capability over cleanly to the teams that will run it
* **Autonomy & Initiative:** Self-directed; looks for the root causes that stop problems coming back

**Required Qualifications**

* Bachelor's degree in Electrical, Computer or Software Engineering, or a related discipline
* 10+ years of embedded firmware or software engineering on hardware products, with working knowledge of electronics, including taking products from design into production
* Experience designing test into embedded products and taking them through production test (test modes, test interfaces, fixtures or automated test stations), hands-on or as technical lead
* Hands-on experience on or directly supporting a production floor
* Root cause analysis across hardware, firmware and software, and a strong grasp of firmware loading, configuration management and software baselines
* Technical leadership of cross-disciplinary engineering work, including directing the work of other engineers
* Ability to obtain and maintain an Australian Government security clearance
* Willingness to travel to US sites from time to time

**Preferred Qualifications**

* Experience in defence, maritime, aerospace, automotive or other safety-critical industries, including work under a quality or certification regime (for example ISO 9001, AS9100 or hazardous-area certification)
* Design-for-test experience: built-in self-test, test points, boundary scan or similar
* Test frameworks, instrument control and hardware-in-the-loop test (for example OpenHTF, NI TestStand, pytest or similar)
* Embedded Linux and RTOS firmware, CAN/CAN-FD or CANopen, and reproducible provisioning (for example Nix/NixOS, Ansible or similar)
* Multi-site or international production, including standing up production at a new site or transferring it between sites
* Treating internal tooling as a product, handing a capability to another team, and a track record of reducing escapes or improving first-pass yield
